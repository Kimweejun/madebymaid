# PPT 요약 정리·결론 도출 (madebymaid-ppt-summary)

## 슬라이드 구성 (본문 5~9장)

표지·목차·결론은 `deck.py`가 자동으로 만든다. 본문은 이 흐름을 따른다.

1. **무엇인가** — 한 문장 정의, 누가 만들었나, 왜 화제인가
2. **어떻게 동작하나** — 구조·핵심 기술
3. **해 본 것 / 확인한 것** — 실제로 확인한 사실 (추측은 "추정"이라고 적기)
4. **장점과 한계**
5. **A4AI 적용** — 어느 사업·과제에 쓸 수 있나 (한국어 음성, 국방 AI, GPU·온디바이스, 에이전트, 제조 AX, 푸드테크, 콘텐츠 AI)
6. **비용과 위험** — 돈·시간·보안·라이선스
7. (필요하면) 비교 대상, 시장 동향, 일정안

## 슬라이드별 규칙

- `title`: 주제어가 아니라 **결론 문장**("~합니다"). 예: "무엇인가"가 아니라 "PR마다 AI가 먼저 코드 리뷰를 해 줍니다".
- `lead`(선택): 제목을 받치는 한 줄 부제.
- `band`(선택): 슬라이드 아래 "핵심" 한 줄. 한 줄을 넘기지 않는다.
- `source`(선택): 외부 자료를 인용했으면 출처. `gloss`(선택): 약어·전문 용어 한 줄 풀이 (청중은 비전문가라고 가정).
- 존댓말 평서문으로 쓰고, 추정치는 "(추정)"이라고 밝힌다. 약점은 숨기지 않되 다음 단계로 쓴다.
- `points`(본문): 1~6줄, 한 줄 40자 안팎. 숫자·고유명사를 살린다.
- `summary`(핵심 요약): **1~3줄**, 한 줄 20자 안팎. 슬라이드 안이 아니라 **웹 페이지에서 슬라이드 그림 옆**에 보인다. 이 슬라이드에서 기억할 것만, 본문을 그대로 복사하지 않는다.
- 사실과 판단을 섞지 않는다. 판단은 A4AI 적용·결론에서.

## 그래프·그림 (visual)

- **분량**: 본문 3장마다 그래프·그림 1개 이상 (본문 5장 → 1개, 6장 → 2개, 9장 → 3개). 한 슬라이드에 하나만. `deck.py`가 개수를 검사한다.
- **숫자 비교가 3개 이상이면 그래프로** 바꾼다. 그래프마다 잘 맞는 자료:

| type | 쓰는 곳 | 규칙 |
|---|---|---|
| `bar` (막대) | 항목별 크기 비교 | series 1개, labels 2~8개 |
| `compare` (비교 막대) | 기존 vs 우리, 전 vs 후 | series 정확히 2개 (비교 대상 먼저, 우리 쪽 나중) |
| `pie` (파이) | 전체 중 비중 (합이 100%인 구성) | series 1개, 조각 2~6개 |
| `line` (꺾은선) | 시간에 따른 변화 (시점 4개 이상) | series 1~3개 |

- 그래프 숫자는 **기사·자료에 실제로 있는 숫자만**. 지어내지 않는다. 추정이면 title에 "(추정)".
- **도식** (`diagram`) — **구조·흐름·순서·인과·비교를 설명하는 슬라이드는 도식이 먼저**다. `madebymaid-diagram-design` 스킬대로 HTML(SVG)을 작업 폴더에 그리고 `file`로 넣으면 `deck.py`가 슬라이드 칸 크기 그림으로 바꿔 넣는다. 근거 있는 사실만 그리고 `caption`("본 도식은 ~ 흐름입니다")·`source`를 단다. 도식 원본은 작업 폴더에만 두고 산출물로 따로 내보내지 않는다.
- **그림** (`image`): 기사·자료의 사진을 작업 폴더에 내려받아 `file`로 넣는다. `caption`은 "본 사진은 ~ 모습입니다"처럼 무엇을 보여 주는지 한 문장, `source`는 출처(필수).
- **맞는 사진도 도식도 없어 분량을 못 채우면** `file` 대신 `prompt`에 생성할 그림을 적는다(무엇을·어떤 구도·테마 색·사람 얼굴 없이). 슬라이드에는 "이미지 생성 대기" 칸이 들어가고, 프롬프트는 `EXP-번호_이미지프롬프트.md`로 모여 이미지 생성 단계에서 채운다. 생성 그림의 해설 앞에는 "개념 이미지 (AI 생성)"이 자동으로 붙는다.

```json
"visual": {"type": "pie", "title": "D.C. 항소법원 3인 재판부 판단", "unit": "명",
           "labels": ["지정 적법", "반대 의견"], "series": [{"name": "판사 수", "values": [2, 1]}], "source": "AI타임스"}
"visual": {"type": "diagram", "file": "cause-flow.html", "caption": "본 도식은 ~ 흐름입니다", "source": "AI타임스 기사 바탕"}
"visual": {"type": "diagram", "layout": "full", "file": "timeline.html", "caption": "본 도식은 ~ 일정입니다"}
"visual": {"type": "image", "file": "article.jpg", "caption": "본 사진은 ~ 모습입니다", "source": "AI타임스 기사 사진"}
"visual": {"type": "image", "prompt": "국방 현장에서 외부 AI와 온디바이스 AI를 비교하는 개념도, 흰 바탕, 사람 얼굴 없이", "caption": "본 그림은 ~ 개념도입니다"}
```

## 결론 도출

- `verdict`: **추천**(바로 시범 적용) / **보류**(조건이 맞으면) / **제외**(쓰지 않음) 중 하나.
- `headline`: 결론 한 줄 (결론 슬라이드 제목이 됨).
- `reasons`: 2~4개. 각 이유에 **근거 슬라이드 번호**(`slides`, 표지=1·목차=2라서 본문은 3번부터)를 단다.
- `next`: 다음 할 일 1~3개 (누가 무엇을).
- 근거 슬라이드가 없는 이유는 쓰지 않는다.

## deck.json 형식

```json
{
  "no": "EXP-1014-01", "maid": "람", "theme": "기술",
  "title": "open-code-review 분석",
  "subtitle": "알리바바의 AI 코드 리뷰 도구를 우리 개발에 쓸 수 있을까",
  "source": "https://github.com/alibaba/open-code-review",
  "slides": [
    {"title": "PR마다 AI가 먼저 코드 리뷰를 해 줍니다", "lead": "알리바바가 공개한 오픈소스 도구",
     "points": ["...", "..."], "summary": ["PR 자동 리뷰 도구", "LLM 교체 가능"],
     "band": "사람 리뷰 전에 1차 점검을 맡길 수 있습니다", "gloss": "LLM: 글을 읽고 쓰는 AI 모델"}
  ],
  "conclusion": {
    "verdict": "추천", "headline": "일반 과제부터 시범 적용하는 것이 좋습니다",
    "reasons": [{"text": "설치와 동작이 바로 됨", "slides": [5]}],
    "next": ["사내 저장소 1곳에 시범 적용"]
  }
}
```

`theme`은 `현장·기술·데이터·사업·연구` 중 보고서 성격에 맞는 하나 (PPT 전체에 적용, `madebymaid-ppt-design` 참고). `deck.py build`가 개수·길이·색 규칙을 검사하고, 어긋나면 무엇을 고칠지 알려 준다.
